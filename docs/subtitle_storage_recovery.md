# Subtitle storage recovery

The current source uses three native arrays and an exact line-table builder; see
[Native arrays and deferred emission](#native-arrays-and-deferred-emission-2026-09-07).
The earlier aggregate experiment below records the evidence leading to that model.

## Layout and source model

The old definition allocated `void* gSubtitleLineTable[256]` and accessed the
following two global arrays by casting that first array to `SubtitleLineTable*`.
The native definition now owns the full storage accessed by its members:

| Member | EN address | Offset | Capacity |
| --- | --- | --- | --- |
| `blocks` | `8033B240` | `000` | 256 allocation pointers |
| `lines` | `8033B640` | `400` | 256 string pointers |
| `times` | `8033BA40` | `800` | 256 floats |

The total extent is `0xC00`, ending at `8033BE40`. The canonical definition in
`include/main/subtitle.h` asserts each member offset and the complete size.
EN symbol ownership now reflects that complete object; the former line/time
global labels are represented by members, not aliases or placement directives.

Retail `subtitleInit` clears exactly 256 block pointers. Build initializes
256 time entries and uses a persistent common base with `+0x400` and `+0x800`
member accesses. Update separately addresses the line and time regions. An
independent audit compared 499 relevant instruction words with the DOL, with
no differences from the extracted retail object.

This supports a coherent storage record, **not proof that the original C used
a struct**. Three adjacent arrays remain a plausible original spelling; no
whole-record allocation, copy, or argument contract distinguishes them. The
native struct preserves the known layout without cross-object overlay access.

Four one-element local arrays are now scalar pointers/integers. Block ownership
uses member indexing, and timing/interpolation locals have semantic names.
The initializer is an ordinary 256-entry pointer loop: its original eight-store
unrolling is generated by MWCC, not spelled as an integer-array overlay.

## Measurements

Baseline: `5065408724`, common game GC/1.3 and unchanged TU flags.

| Function | Before bytes | After bytes | After fuzzy |
| --- | ---: | ---: | ---: |
| `subtitleUpdateAndDraw` | 544 | 548 | 94.13433% |
| `mainLoopDoGameText` | 124 | 124 | 100% |
| `subtitleStop` | 184 | 188 | 96.847824% |
| `subtitleBuildLineTable` | 960 | 964 | 99.1875% |

TU fuzzy match regresses `99.3459% -> 97.50333%`; exact functions fall from
three to one. Stop and Build add a base-pointer move and exchange saved-register
assignments. Update changes field-address materialization. No arithmetic or
branch predicates were intentionally changed. Data sections remain byte-identical:
`0xC00` BSS and 32 bytes of literals. Loaded pool-value progression also matches
retail in both relevant functions; this does not prove instruction equality.

All nine functions in `textrender_drawbox` remain exact, with identical function
bytes, allocated sections, and named storage. Its object hash changes only through
anonymous relocation-symbol renumbering. Every other built source object is
byte-identical to the baseline. Semantic local renames in subtitle are themselves
object-byte-neutral.

Retain the unused `previousCharacterTotal` snapshot: deleting it removes four
retail conversion-preparation instructions before the look-ahead bounds test.
The original reason for those dead stores remains unknown.

## Behavior and validation

`tools/test_subtitle_runtime.py` checks the built object's storage and executes
production subtitle scheduling, building, stopping, and initialization code at
host O0/O2. Its 139 scenarios produce 278 calls. Text wrapping, command parsing,
allocation release, drawing, and charset/directory services are controlled mocks.
The tests cover partial initialization, failed wraps, integer timestamp truncation,
character-weighted interpolation, reverse color selection and byte narrowing,
free-delay restoration, readiness gates, and single-step line advancement.

Negative controls fail independently: clearing `lines` instead of `blocks` gives
two failures; changing frame-to-second division from 60 to 30 gives sixteen.

Preserved retail quirks and test limits:

- Init clears blocks only; Stop leaves line/time pointers, counts and elapsed state stale.
- A timestamp is written before wrapping succeeds; frame components use integer division.
- Update parses the outgoing line and advances at most once. The final entry in a
  multi-line track acts as an end boundary; zero/one-line tracks do not automatically stop.
- Insertion is unchecked at the 256-entry boundaries. No capacity was enlarged or clamped.
- Interpolation scans up to index 254 rather than the populated line count, can
  inspect stale strings, and has no zero-character-total guard. Those invalid/stale
  input paths are not exercised by the host harness or made safe by this change.
- The backwards command walk's unused final pointer decrement remains unchanged.

Both `ninja all_source` and the strict DOL checksum gate pass. Subtitle remains
NonMatching, so the checksum uses retail subtitle code; it does validate the
still-Matching initializer consumer. Host tests are not PPC floating-point emulation.

## Regional symbol ownership follow-up

The four other version configs now assign the complete `0xC00` extent to
`gSubtitleLineTable`, matching the common source definition. Their existing
subtitle BSS split windows already covered exactly those extents; no region's
addresses, split boundaries, or expected checksums change.

| Version | Table base | End | Evidence checked |
| --- | --- | --- | --- |
| EN rev1 | `8033BEA0` | `8033CAA0` | Config spans and retail builder/initializer |
| JP | `8033B360` | `8033BF60` | Config spans and retail builder/initializer |
| PAL rev0 | `8033C9E0` | `8033D5E0` | Existing config spans only |
| PAL rev1 | `8033CBA0` | `8033D7A0` | Config spans and retail builder/initializer |

The checked regional builders contain 240 instructions and their initializers
48. Relative to EN, differences are call displacements, global addresses,
and SDA offsets; the member offsets and 256-entry initialization stay the same.
The local artifact under `orig/GSAP01/sys/main.dol` identifies as **PAL rev1**
by SHA-1 `c1a6ccdc61c7e719e20ea7cc59c8de09fd183e66`, matching
`config/GSAP01_rev1/build.sha1`. Its subtitle base is `8033CBA0`, so it was
not treated as evidence for the PAL rev0 addresses. The artifact was left in
place. This audit does not claim successful builds of the secondary versions.

## Native arrays and deferred emission (2026-09-07)

The combined `SubtitleLineTable` definition is replaced by three arrays, each
with its existing 256-entry capacity:

| Array | EN address | BSS offset | Bytes |
| --- | --- | --- | ---: |
| `gSubtitleBlocks` | `8033B240` | `000` | 1024 |
| `gSubtitleLines` | `8033B640` | `400` | 1024 |
| `gSubtitleTimes` | `8033BA40` | `800` | 1024 |

Definitions precede the function bodies in reverse emitted storage order.
The complete TU uses deferred emission, with ordinary function definitions in
reverse retail order. GC/1.3, level 1, and the existing optimization switches
remain unchanged. MWCC supplies its own shared BSS base for the builder's
indexed accesses; no source overlay, alias, or section directive is needed.
No whole-record consumer requires the former aggregate.

Three controls distinguish the storage and emission changes. Deferred emission
alone leaves the aggregate builder at 241 instructions. Native arrays without
deferred emission produce 243. Together they reproduce all 240 retail
instructions and the full 960-byte function. These controls support the native
array model without claiming it uniquely proves the original source spelling.

| Function | Previous fuzzy | Current fuzzy | Current C bytes |
| --- | ---: | ---: | ---: |
| `subtitleBuildLineTable` | 99.1875% | **100%** | 960 |
| `subtitleUpdateAndDraw` | 94.13433% | 97.01492% | 548 |
| `subtitleStop` | 96.847824% | 96.847824% | 188 |
| `mainLoopDoGameText` | 100% | 100% | 124 |

The latter two bodies are byte-identical. The unit gains 960 matched code
bytes and reaches 2/4 exact functions, improving aggregate fuzzy match from
97.50333% to 98.79157%. All 3,104 data bytes retain their contents, layout and
exact credit. The compiler adds only its local zero-size BSS base symbol;
the three named allocations replace the combined symbol at unchanged offsets.

The shared initializer in `textrender_drawbox.c` now clears `gSubtitleBlocks`
directly. Its complete object's function bytes, allocated sections and named
symbol layouts are unchanged; resolving relocations and accounting for the
renamed external base preserves every destination. All five regional symbol
configs describe the same three 0x400-byte spans inside their existing subtitle
BSS windows. No regional addresses or split boundaries move; only EN is built
and matched in this pass.

`tools/test_subtitle_runtime.py` checks the three PPC symbol extents and still
runs the same 139 scenarios at O0 and O2 (278 host calls). All seven tests pass.
The fixture uses the native definitions; target pointer-storage size assertions
are checked in the PPC build rather than imposed on wider host pointers.
Previously documented timing, allocation and stale-input quirks remain.

Both `ninja all_source` and the strict checksum gate pass, and the linked EN
DOL is byte-identical to retail. Subtitle remains `NonMatching` because its
update and stop bodies still differ; the builder's exact credit comes from
objdiff, with the DOL gate checking integration separately.
