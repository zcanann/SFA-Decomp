# Standard reverb handler constants

`dolphin/axfx/reverb_std_callback.c` now defines the three constants its existing
assembly handler loads: `0.3f`, `0.6f`, and the signed-integer conversion bias
`4503601774854144.0`. They previously remained extern declarations backed by an
autogenerated pool unit. Ordinary C definitions emit the complete 16-byte pool
with eight-byte alignment; no section pragma, assembly data, duplicate literal,
compiler change or force-active entry is needed.

The reference implementation in
`reference_projects/super_mario_strikers/src/Dolphin/axfx/reverb_std.c` defines
the same two float constants and double immediately before its assembly
handler. This corroborates their role; retail instructions and bytes establish
the actual SFA ownership and placement.

The complete extracted EN relocation scan finds six references to these three
symbols, all in `HandleReverb2`: one high/low address pair for each constant.
Their instruction offsets are 0x24, 0x2C and 0x34. Decoding those pairs in each
verified regional DOL establishes the following ranges independently of a
global address delta:

| Version | Pool range |
| --- | --- |
| EN | `803E7920..803E7930` |
| EN rev1 | `803E85B8..803E85C8` |
| JP | `803E7A40..803E7A50` |
| PAL rev1 | `803E9318..803E9328` |

Every range contains `3E99999A 3F19999A 43300000 80000000`. The source symbols
occupy offsets zero, four and eight, with sizes four, four and eight. The six
relocations retain their kinds, sites, names and zero addends; their targets
become definitions within the owner instead of undefined imports. The handler,
callback, exception records and existing symbol positions remain unchanged.

After the EN pool claim, `version_progress.py --write` independently projects
the same ranges and names into the other three verified configurations. Its
unrelated normalization and removal of the previously verified renderer BSS
claim are not retained. No text boundary or compiler profile changes.

Full source builds and fresh objdiff reports pass in all four versions. Each
gains **16 matched and completed data bytes**; the callback unit remains exact
at 984 code bytes and advances from 20 to 36 data bytes. Total code and data
denominators stay unchanged. All other compiled source objects are byte-identical.
EN's strict retail checksum passes with the compiled callback and its new pool
in the matching link. Formatting is verified separately for unchanged objects.
